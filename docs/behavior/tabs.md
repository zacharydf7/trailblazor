# Tabs

Pattern: [Tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)

Familiar apps: Windows property dialogs, browser developer tools, VS Code's settings

## Focus

- [x] Tab reaches the list once, on the selected tab. `TbTabsTests.Render_ShouldLinkEachTabToItsPanel_WhenCalled`
- [x] With the selected tab disabled, or none selected, Tab reaches the first enabled tab. `TbTabsTests.Render_ShouldMakeTheFirstEnabledTabReachable_WhenTheSelectedTabIsDisabled`
- [x] Tab from the selected tab moves into its panel when the panel starts with text. `TabsTests.Tabs_ShouldMoveFocusIntoThePanel_WhenTabIsPressedOnTheSelectedTab`
- [x] A panel that starts with a control is no tab stop of its own, so Tab goes from the selected tab to that control. That holds when the tabs were set up while hidden, and when a kept panel is shown again. Text that names something, in a label, a legend or an element an `aria-labelledby` points at, doesn't count as coming first. Neither does anything not displayed, anything hidden from screen readers with `aria-hidden`, an image marked as decoration with `alt=""`, or a control Tab skips because it shares one tab stop with others, such as the tabs before a nested list's selected one. A control that names what it opens, as a menu's button does, still counts as a control. `TabsStopsTests.Tabs_ShouldGoFromTheTabToThePanelsFirstControl_WhenThePanelStartsWithOne`, `TabsStopsTests.Tabs_ShouldGoToTheNestedSelectedTabAndThenItsPanel_WhenAPanelStartsWithNestedTabs`, `TabsStopsTests.Tabs_ShouldGoToThePanelsFirstControlAgain_WhenAKeptPanelsTabIsSelectedAgain`, `TabsStopsTests.Tabs_ShouldGoFromTheTabToThePanelsFirstControl_WhenTheTabsWereSetUpWhileHidden`, `TabsStopsTests.Tabs_ShouldDecideEachPanelsStopByWhatPeopleReadFirst_WhenPanelsStartInDifferentWays`
- [x] A panel that starts with text or a picture is a tab stop, so the Tab key reaches content that has no controls. Text in something only script can focus, such as a list that scrolls, counts as text, and so does text inside an element with `display: contents`. `TabsStopsTests.Tabs_ShouldStopOnThePanel_WhenItStartsWithText`, `TabsStopsTests.Tabs_ShouldDecideEachPanelsStopByWhatPeopleReadFirst_WhenPanelsStartInDifferentWays`
- [x] The stop follows changes to the panel: it goes when a control comes first, and comes back when one no longer does, as elements are added or removed, or a control is turned off or hidden with `hidden`. A panel that has focus keeps its stop until focus leaves it, so focus isn't lost. `TabsStopsTests.Tabs_ShouldTakeThePanelsStopAwayAndGiveItBack_WhenAControlTakesTheTextsPlaceAndGoesAgain`, `TabsStopsTests.Tabs_ShouldGiveThePanelItsStopBack_WhenItsFirstControlIsTurnedOff`, `TabsStopsTests.Tabs_ShouldKeepThePanelsStopAndItsFocus_WhenAControlArrivesWhileThePanelHasFocus`, `TabsStopsTests.Tabs_ShouldTakeThePanelsStopAway_WhenFocusLeavesAPanelThatKeptItsStopForIt`
- [x] The stop is decided by the time the list is marked ready with `data-ready`, so a test that waits for the mark finds the stop settled. `TabsStopsTests.Tabs_ShouldHaveDecidedThePanelsStop_WhenTheListIsMarkedReady`
- [x] `FocusablePanels` set to `Always` makes every shown panel a tab stop, and `Never`, which a ribbon uses, makes none a stop. Until the page is interactive, and on a static page, the startup script decides the shown panel's stop the way the interactive script does: as it loads, after an enhanced navigation and when a tab is selected. `TabsTests.Tabs_ShouldTabFromThePanelOutOfTheTabs_WhenThePageIsStatic`, `TabsStopsTests.Tabs_ShouldGoFromTheTabToThePanelsFirstControl_WhenThePageIsStaticAndThePanelStartsWithOne`, `TabsStopsTests.Tabs_ShouldStopOnlyOnAPanelThatStartsWithText_WhenAStaticPagesTabsAreSwitched`, `TabsStopsTests.Tabs_ShouldGoFromTheTabToThePanelsFirstControl_WhenEnhancedNavigationBringsAStaticPagesTabs`, `TabsStopsTests.Tabs_ShouldStopOnAPanelThatStartsWithAControl_WhenThePageIsStaticAndFocusablePanelsIsAlways`, `TabsStopsTests.Tabs_ShouldPassOverAPanelThatStartsWithText_WhenThePageIsStaticAndFocusablePanelsIsNever`, `TbTabsTests.FocusablePanels_ShouldSetTheShownPanelsStopAndMarkTheList_WhenGivenEachChoice`, `TabsStopsTests.Tabs_ShouldGiveThePanelItsStopBack_WhenFocusablePanelsBecomesAlways`, `TabsStopsTests.Tabs_ShouldLeaveThePanelNoStop_WhenFocusablePanelsBecomesNeverAndThePanelStartsWithText`, `RibbonTests.Ribbon_ShouldSwitchTabsAndRefuseAHelpersClick_WhenThePageIsStatic`
- [x] A focused tab shows a focus ring. `trailblazor.css`
- [x] A tab that can close is described by "Press Delete to close", or `Labels.CloseHint`, since nothing else tells a screen reader user how. A screen reader on a touch screen has no Delete key, so an app with closable tabs should offer another way to close them, such as a close button in the panel. `TbTabsTests.Render_ShouldDescribeAClosableTabByHowToCloseIt_WhenATabCanClose`, `TbTabsTests.Labels_ShouldWordTheCloseHint_WhenGiven`
- [x] Focus stays on the same tab when a tab renders before it. `TabsTests.Tabs_ShouldKeepFocusOnTheSameTab_WhenALateTabRendersBeforeIt`
- [x] When the focused tab that goes away was the selected one, focus moves to the enabled tab selected in its place. The app can choose that tab as it removes the other, by `ActiveKey` or by `ActiveIndex`, even one it adds in the same render. Focus gets there in one move, whether the tab was closed or removed some other way, and goes to the tab beside it when no enabled tab is selected. `TabsFollowTests.Tabs_ShouldMoveFocusOnceToTheTabTheAppSelects_WhenTheSelectedTabGoesAway`, `TabsFollowTests.Tabs_ShouldFocusTheTabBesideIt_WhenTheSelectedTabGoesAwayAndTheAppSelectsNone`, `TabsFollowTests.Tabs_ShouldFocusTheTabBesideIt_WhenTheSelectedTabGoesAwayAndTheAppSelectsADisabledTab`, `TbTabsTests.Close_ShouldFocusTheTabTheAppSelects_WhenTheClosedTabWasTheSelectedOne`, `TbTabsTests.Close_ShouldFocusTheTabBesideIt_WhenTheClosedTabWasSelectedAndTheAppSelectsNone`, `TbTabsTests.Close_ShouldFocusTheTabBesideIt_WhenTheClosedTabWasSelectedAndTheAppSelectsADisabledTab`, `NavigationExampleTests.TabsClosableExample_ShouldRemoveTheTabAndFocusTheNextOne_WhenATabIsClosed`
- [x] Once a closed tab that wasn't the selected one is removed, focus moves to the next enabled tab, or to the one before it when no enabled tab follows, even when the app selects another tab as it removes the tab. A tab the parent keeps open leaves focus alone, and so does one it removes later after focus has left it. `TbTabsTests.Close_ShouldFocusTheTabBesideIt_WhenTheClosedTabWasNotSelectedAndTheAppSelectsAnother`, `NavigationExampleTests.TabsClosableExample_ShouldFocusTheTabBefore_WhenTheLastTabIsClosed`, `TbTabsTests.Close_ShouldLeaveFocusAlone_WhenTheParentKeepsTheTabAndRemovesItLater`, `TbTabsTests.Close_ShouldFocusTheEnabledTabBefore_WhenTheNextTabIsDisabled`, `TbTabsTests.Close_ShouldFocusTheNextTab_WhenOnCloseRemovesTheTabAfterAwaiting`
- [x] A focused tab that wasn't selected, removed by the parent by any other route, such as a key of its own, also hands focus to the next enabled tab, or to the one before it when no enabled tab follows, even when the app selects another tab as it removes the tab. A tab removed with it, or a disabled one, is passed over. Removing a tab after focus has already left it, for a field or the page, leaves focus where it is. `TabsRemoveTests.Tabs_ShouldFocusTheNextTab_WhenTheParentRemovesTheFocusedOne`, `TabsFollowTests.Tabs_ShouldFocusTheTabBesideIt_WhenAFocusedTabThatIsNotSelectedGoesAsTheAppSelectsAnother`, `TabsRemoveTests.Tabs_ShouldFocusTheNextTab_WhenTheParentRemovesTheFocusedOneAfterAFocusoutThatKeptFocus`, `TabsRemoveTests.Tabs_ShouldPassOverTabsRemovedWithItAndDisabledOnes_WhenTheParentRemovesTheFocusedOne`, `TabsRemoveTests.Tabs_ShouldFocusTheEnabledTabBefore_WhenTheParentRemovesTheFocusedLastOne`, `TabsRemoveTests.Tabs_ShouldLeaveFocusAlone_WhenTheParentRemovesATabAfterFocusLeftItForAField`, `TabsRemoveTests.Tabs_ShouldLeaveFocusOnThePage_WhenTheParentRemovesATabAfterFocusLeftItForThePage`
- [x] Delete and Backspace have their default prevented on every tab, even one that can't close, so a shortcut of the app's that skips prevented keys doesn't run for them. `TabsTests.Tabs_ShouldKeepDeleteAndBackspaceFromThePagesOwnShortcuts_WhenTheTabCannotClose`

## Not applicable

- Tab leaving the list from an unselected tab, with manual activation: when that tab comes before the selected one, Tab stops on the selected tab first, since that tab holds the list's one tab stop.
